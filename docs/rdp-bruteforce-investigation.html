1. Kiến thức nền

Hãy coi máy chủ là một khách sạn. Security log là sổ của bảo vệ. 4625 = "có người quẹt thẻ sai ở cửa". 4624 = "cửa đã mở cho ai đó". Logon Type = cửa nào được mở (cửa phòng, cửa dịch vụ, cửa từ xa...). Logon ID = số vòng tay phát cho khách khi vào: mọi việc vị khách làm sau đó (dùng đặc quyền, chạy chương trình, ra về) đều được ghi kèm số vòng tay này. Đó chính là sợi dây nối event "cha" với event "con".

Vì sao brute force RDP lại hiện là Type 3 chứ không phải 10? RDP hiện đại bật NLA (Network Level Authentication): bảo vệ kiểm tra thẻ ngay ở cổng ngoài (Type 3, qua NTLM/CredSSP) trước khi cho bạn vào sảnh. Chỉ khi qua cổng rồi bạn mới được dẫn tới phòng và mở cửa phòng (Type 10). Kẻ brute force bị chặn ngay ở cổng, nên chỉ để lại 4625 Type 3.

Mở PowerShell và tạo hàm "bóc" EventData

Mỗi event là một bản XML. Cột Message chỉ là chữ để người đọc; muốn lọc/đếm chính xác thì phải bóc các trường <Data Name="..."> ra thành cột. Hàm dưới đây biến mỗi event thành một "hàng Excel".

$log = "C:\Lab\RDP-Security.evtx"

function ConvertTo-EvtObject {
  process {
    $x = [xml]$_.ToXml()
    $o = [ordered]@{
      TimeUTC  = $_.TimeCreated.ToUniversalTime()
      Id       = $_.Id
      RecordId = $_.RecordId
    }
    foreach ($d in $x.Event.EventData.Data) { $o[$d.Name] = $d.'#text' }
    [pscustomobject]$o
  }
}

# Đọc toàn bộ file một lần, dùng lại cho các bước sau
$all = Get-WinEvent -Path $log -Oldest | ConvertTo-EvtObject
$all | Group-Object Id | Select-Object Count, Name
Count Name
----- ----
 1559 4625
    8 4624
TimeCreated mặc định hiển thị theo giờ máy bạn (VN = UTC+7). Mình đổi sang UTC để khớp với các báo cáo / SIEM. Giờ VN = giờ UTC + 7.

4.4 Vì sao NLA (Type 3) và RDP (Type 10) không chung Logon ID?

Ở cổng, bảo vệ phát cho bạn một vé tạm (Logon ID 0x9C3016C0) chỉ để xác nhận bạn là ai. Vào tới phòng, lễ tân phát vòng tay chính thức (0x9C306841). Hai giấy tờ khác số, nhưng cùng tên người, cùng biển số xe (IP), cách nhau vài giây. Vì vậy ta nối chúng bằng sợi dây #5 (thời gian + IP + SID).
