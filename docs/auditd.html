1. Definition1. Định nghĩa

auditd is Linux's built-in auditing service. The kernel watches system calls that match the rules you set, and auditd writes the results to /var/log/audit/audit.log.

auditd là dịch vụ kiểm toán có sẵn của Linux. Kernel theo dõi các system call khớp với rule bạn đặt, rồi auditd ghi kết quả vào /var/log/audit/audit.log.

Analogy: syslog is a diary each employee writes themselves — anyone who doesn't want to write simply doesn't. auditd is a camera at the door, run by the building (the kernel): programs can't opt out of being filmed.
Ví von: syslog giống sổ nhật ký mỗi nhân viên tự viết — ai không muốn viết thì thôi. auditd giống camera gắn ở cửa do tòa nhà (kernel) quản lý: chương trình không tự né được.

2. Install & manage2. Cài đặt & quản lý

# Ubuntu/Debian
sudo apt install auditd audispd-plugins
# RHEL/Rocky/Fedora (usually preinstalled)
sudo dnf install audit

sudo systemctl enable --now auditd
sudo auditctl -s     # status: enabled=1 means logging
sudo auditctl -l     # list loaded rules

Note: on RHEL, systemctl restart auditd is refused by design — use sudo service auditd restart.

Lưu ý: trên RHEL, systemctl restart auditd bị từ chối có chủ đích — dùng sudo service auditd restart.

3. Reading a rule3. Cách đọc một rule

Analogy: every rule is an instruction to a guard: "always record → whenever someone does X → but only if Y → and label it Z."
Ví von: mỗi rule là một câu dặn bảo vệ: "luôn ghi lại → khi ai làm việc X → nhưng chỉ khi thỏa Y → và dán nhãn Z."

Type 1 — watch a file or folder

Kiểu 1 — theo dõi file hoặc thư mục

-w /etc/passwd -p wa -k identity

Watch (-w) /etc/passwd, record writes and attribute changes (-p wa), label it identity (-k). Permissions: r read, w write, x execute, a attribute change. A watch on a folder covers every file inside.

Theo dõi (-w) /etc/passwd, ghi lại khi có ghi hoặc đổi thuộc tính (-p wa), dán nhãn identity (-k). Quyền: r đọc, w ghi, x thực thi, a đổi thuộc tính. Đặt lên thư mục thì mọi file bên trong đều được theo dõi.

Type 2 — watch a system call

Kiểu 2 — theo dõi system call

-a always,exit -F arch=b64 -S execve -F exe=/usr/bin/wget -k proc_wget

4. Sample SOC ruleset4. Bộ rule mẫu cho SOC

Focus on high-risk behaviour instead of logging everything. Save as /etc/audit/rules.d/50-soc.rules and adjust to your machine.

Tập trung vào hành vi rủi ro cao thay vì ghi mọi thứ. Lưu thành /etc/audit/rules.d/50-soc.rules rồi chỉnh theo máy của bạn.

## Clear old rules, raise buffer, warn on lost events
-D
-b 8192
-f 1

## 1. Commands run by real users
-a always,exit -F arch=b64 -S execve -F auid>=1000 -F auid!=unset -k exec_user
-a always,exit -F arch=b32 -S execve -F auid>=1000 -F auid!=unset -k exec_user

## 2. Accounts & privileges
-w /etc/passwd -p wa -k identity
-w /etc/shadow -p wa -k identity
-w /etc/group -p wa -k identity
-w /etc/sudoers -p wa -k priv_esc
-w /etc/sudoers.d/ -p wa -k priv_esc

## 3. SSH
-w /etc/ssh/sshd_config -p wa -k sshd_conf
-w /root/.ssh/ -p wa -k ssh_keys

## 4. Persistence via cron & systemd
-w /etc/crontab -p wa -k cron
-w /etc/cron.d/ -p wa -k cron
-w /var/spool/cron/ -p wa -k cron
-w /etc/systemd/system/ -p wa -k systemd_persist

## 5. Download tools
-w /usr/bin/wget -p x -k download_tool
-w /usr/bin/curl -p x -k download_tool

## 6. Python network connections (reverse shell)
-a always,exit -F arch=b64 -S connect -F exe=/usr/bin/python3.12 -k net_python

## 7. Tampering with audit logs or config
-w /var/log/audit/ -p wa -k audit_tamper
-w /etc/audit/ -p wa -k audit_tamper
-w /usr/sbin/auditctl -p x -k audit_tamper

## Lock config — uncomment once stable
# -e 2
sudo augenrules --load   # merge rules.d and load into the kernel
sudo auditctl -l         # confirm rules are loaded
sudo auditctl -s         # "lost" should stay at 0
  • exe= needs the real path. /usr/bin/python3 is usually a symlink — check with readlink -f /usr/bin/python3.
  • exe= cần đường dẫn thật. /usr/bin/python3 thường là symlink — kiểm tra bằng readlink -f /usr/bin/python3.
  • -e 2 locks all rules until reboot, even for root. Enable only once the ruleset is stable.
  • -e 2 khóa mọi rule đến lần khởi động lại, kể cả với root. Chỉ bật khi bộ rule đã ổn định.
  • -f 1 only warns on lost events; -f 2 causes a kernel panic — not for ordinary machines.
  • -f 1 chỉ cảnh báo khi mất sự kiện; -f 2 gây kernel panic — không dùng cho máy thường.

7. Investigation walkthrough7. Kịch bản điều tra mẫu

Scenario: an alert says a Linux host just downloaded a file from GitHub. Rebuild the chain: who, what was downloaded, what ran next, which files were touched.

Tình huống: cảnh báo cho biết một máy Linux vừa tải file từ GitHub. Dựng lại chuỗi hành động: ai, tải gì, chạy gì tiếp, chạm file nào.

  1. Overview. aureport -k --summary and aureport -x --summary to spot unusual keys and programs.
  2. Find the download. ausearch -i -k proc_wget | grep proctitle — the URL end gives the source and original filename.
  3. Take the "fingerprint". From its SYSCALL line note time, auid, uid, pid, ppid, tty.
  4. What did they do next? ausearch -i -ul <auid> -sc execve --start <time> | grep proctitle
  5. Actions with no key. If the file is a scanner, search everything: ausearch -i | grep -i <tool>. Target ranges appear in a1, a2…
  6. Process tree. ausearch -i -pp <pid> for children, ausearch -i -p <ppid> for the parent.
  7. Sensitive files. ausearch -i -k file_thmsecret — results are chronological, so the first event is the first open.
  8. Persistence & cleanup. Check -k identity, cron, sshd_conf, audit_tamper in the same window.
  9. Write the timeline. Time · user · command · meaning — the final deliverable.
  1. Nhìn tổng quan. aureport -k --summary và aureport -x --summary để thấy key và chương trình bất thường.
  2. Tìm lần tải file. ausearch -i -k proc_wget | grep proctitle — cuối URL cho biết nguồn và tên file gốc.
  3. Ghi "dấu vân tay". Từ dòng SYSCALL chép lại thời gian, auid, uid, pid, ppid, tty.
  4. Họ làm gì tiếp? ausearch -i -ul <auid> -sc execve --start <thời gian> | grep proctitle
  5. Hành động không có key. Nếu file là công cụ quét, tìm trong toàn bộ log: ausearch -i | grep -i <tên công cụ>. Dải mạng nằm ở a1, a2…
  6. Cây tiến trình. ausearch -i -pp <pid> xem tiến trình con, ausearch -i -p <ppid> đi ngược lên cha.
  7. File nhạy cảm. ausearch -i -k file_thmsecret — kết quả xếp theo thời gian, sự kiện đầu tiên là lần mở đầu tiên.
  8. Persistence & xóa dấu vết. Kiểm tra -k identity, cron, sshd_conf, audit_tamper trong cùng khoảng thời gian.
  9. Viết dòng thời gian. Giờ · user · lệnh · ý nghĩa — kết quả cuối cùng của cuộc điều tra.
