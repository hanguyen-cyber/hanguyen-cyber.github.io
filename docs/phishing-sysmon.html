🧠 Tư duy điều tra: đi theo "con đường" của file độc

Hãy hình dung Sysmon như hệ thống camera an ninh trong một toà nhà. Mỗi Event ID là một loại camera chuyên quay một kiểu hành động: camera ở cửa ra vào (process start), camera ở kho (file tạo mới), camera ở tổng đài điện thoại (DNS)… Muốn biết kẻ gian làm gì, ta không xem lần lượt hết các camera, mà đi theo hành trình của nó và mở đúng camera cho từng chặng.

🛠️ Step by step

Chạy trên Windows PowerShell 5.1 hoặc PowerShell 7 trên Windows (Get-WinEvent không có trên Linux/macOS). Sửa $Path thành đường dẫn thật của file .evtx.

B0Nạp log và "dịch" event thành bảng dễ đọc

Mặc định Get-WinEvent trả về Message là một khối chữ dài, khó lọc. Hàm dưới đây đọc phần XML của từng event và biến mỗi <Data Name="..."> thành một cột riêng (Image, ProcessId, TargetFilename…), giống như tách một tờ hoá đơn thành từng ô trong Excel.

$Path = "C:\Labs\Phishing-Sysmon.evtx"   # <-- sửa đường dẫn
$Raw  = Get-WinEvent -Path $Path -Oldest

function ConvertTo-SysmonObject {
    process {
        $xml = [xml]$_.ToXml()
        $o = [ordered]@{
            RecordId = $_.RecordId
            EventId  = $_.Id
            Time     = $_.TimeCreated        # giờ theo máy bạn
        }
        foreach ($d in $xml.Event.EventData.Data) { $o[$d.Name] = $d.'#text' }
        [pscustomobject]$o
    }
}

$Ev = $Raw | ConvertTo-SysmonObject
$Ev.Count     # 48

B1Nhìn tổng quan: log có những loại event nào?

$Ev | Group-Object EventId | Sort-Object Count -Descending | Select-Object Count, Name

Kết quả: ID 1 (14), 15 (14), 10 (6), 22 (4), 11 (4), 13 (3), 2, 12, 5 (mỗi loại 1). Có ID 11/15 → có file được tạo; có ID 22 → có tra DNS. Đủ "camera" cho cả 4 câu hỏi.

B2File nào được download qua browser? ID 11 ID 15

a) File do browser tạo ra:

$Ev | Where-Object { $_.EventId -in 11,15 -and $_.Image -match 'msedge|chrome|firefox' } |
      Select-Object RecordId, Time, EventId, ProcessId, TargetFilename

Bạn sẽ thấy chuỗi: 9136f7a3-...tmp → Unconfirmed 109024.crdownload → top-cats.zip. Đây là cách Edge tải file: ghi tạm vào file .crdownload, tải xong thì đổi tên thành tên thật. Để ý MD5 của .crdownload và top-cats.zip giống nhau (E456B52C…), tức là cùng một file.

b) Xác nhận bằng Mark-of-the-Web (lấy luôn URL nguồn):

$Ev | Where-Object { $_.EventId -eq 15 -and $_.Contents -match 'HostUrl' } |
      Select-Object RecordId, Time, Image, TargetFilename, Contents | Format-List
Kết quả mong đợi 
RecordId       : 4822
Image          : C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe
TargetFilename : C:\Users\Administrator\Downloads\top-cats.zip:Zone.Identifier
Contents       : [ZoneTransfer]  ZoneId=3  ReferrerUrl=http://10.14.97.15/top-cats-2025/
                 HostUrl=http://10.14.97.15/top-cats-2025/top-cats.zip
→ File tải về: top-cats.zip.

B3User giải nén file đáng ngờ vào thư mục nào? ID 11 ID 15

Khi user mở file zip bằng Windows Explorer rồi kéo/thả hoặc "Extract", process tạo file là explorer.exe chứ không phải browser. Lọc theo đó:

$Ev | Where-Object { $_.EventId -in 2,11,15 -and $_.Image -like '*explorer.exe' } |
      Select-Object RecordId, Time, EventId, TargetFilename, Contents | Format-List

Hoặc chỉ lấy thư mục của những file có "tem" trỏ về file zip mẹ:

$Ev | Where-Object { $_.EventId -eq 15 -and $_.Contents -match 'ReferrerUrl=.*\.zip' } |
      ForEach-Object { Split-Path ($_.TargetFilename -replace ':Zone\.Identifier$','') } |
      Sort-Object -Unique
Kết quả mong đợi 3 file được bung ra: best-cat.jpg.exe, nice-cat-1.jpg, nice-cat-2.png, đều có ReferrerUrl=C:\Users\Administrator\Downloads\top-cats.zip.
→ Thư mục: C:\Users\Administrator\Pictures.
Ghi lại ProcessGuid của explorer: {c5d2b969-2e42-682b-4a02-000000001801} (PID 2788) để dùng ở bước sau.

B4PID của phishing malware khi được chạy ID 1

File chạy bằng double-click thì cha của nó là explorer.exe. Liệt kê các process con của explorer:

$Ev | Where-Object { $_.EventId -eq 1 -and $_.ParentImage -like '*explorer.exe' } |
      Select-Object RecordId, Time, ProcessId, Image, CommandLine

Hoặc săn thẳng file đuôi kép (kiểu .jpg.exe — Windows ẩn đuôi .exe nên user chỉ thấy "best-cat.jpg"):

$Mal = $Ev | Where-Object { $_.EventId -eq 1 -and $_.Image -match '\.(jpg|jpeg|png|pdf|docx?|xlsx?)\.exe$' }
$Mal | Select-Object Time, ProcessId, ProcessGuid, Image, ParentProcessId, ParentImage
Kết quả mong đợi 2 process mspaint.exe (PID 1668, 4468) mở 2 ảnh mồi, và C:\Users\Administrator\Pictures\best-cat.jpg.exe.
→ PID malware: 5484, ProcessGuid {c5d2b969-d0fa-682c-2b05-000000001801}.

B5Domain độc hại mà malware cố kết nối tới ID 22

Lấy GUID của malware ở B4 rồi tìm mọi DNS query có cùng GUID:

$Ev | Where-Object { $_.EventId -in 3,22 -and $_.ProcessGuid -eq $Mal.ProcessGuid } |
      Select-Object RecordId, Time, ProcessId, QueryName, QueryStatus, QueryResults, DestinationIp
Kết quả mong đợi 2 query lúc 18:59:09 và 18:59:18 tới rjj.store, QueryStatus = 9003 (tên miền không tồn tại / không phân giải được), QueryResults = -. Không có Event ID 3 nào vì không có IP để kết nối.

Bonus — xem toàn bộ "nhật ký" của malware (mọi Event ID mang GUID của nó):

$Ev | Where-Object { $_.ProcessGuid -eq $Mal.ProcessGuid } |
      Select-Object RecordId, Time, EventId, Image, QueryName

→ ID 1 (bắt đầu) → ID 22 ×2 (tra DNS) → ID 5 (kết thúc lúc 18:59:37).

B6Vẽ cây process cha – con

function Show-Tree($Guid, $Indent = 0) {
    $kids = $Ev | Where-Object { $_.EventId -eq 1 -and $_.ParentProcessGuid -eq $Guid }
    foreach ($k in $kids) {
        '{0}|-- [{1}] {2}' -f (' ' * $Indent), $k.ProcessId, $k.CommandLine
        Show-Tree $k.ProcessGuid ($Indent + 4)
    }
}
Show-Tree '{c5d2b969-2e42-682b-4a02-000000001801}'   # explorer.exe (PID 2788)
Show-Tree '{c5d2b969-ce8e-682c-e604-000000001801}'   # msedge.exe  (PID 3504)

⚡Cách lọc nhanh hơn khi log lớn: lọc ngay lúc đọc

Với log hàng trăm nghìn event, đừng nạp hết rồi mới Where-Object. Hãy để Windows lọc sẵn:

# Theo Event ID
Get-WinEvent -FilterHashtable @{ Path = $Path; Id = 22 }

# Theo Event ID + giá trị field (XPath, so khớp CHÍNH XÁC, không có "contains")
Get-WinEvent -Path $Path -FilterXPath "*[System[EventID=22] and EventData[Data[@Name='ProcessId']='5484']]" |
    Format-List TimeCreated, Message

B0Mở file .evtx (và vai trò của file .MTA)

  1. Tạo một thư mục, ví dụ C:\Labs\, đặt Phishing-Sysmon.evtx vào đó.
  2. Tạo thư mục con C:\Labs\LocaleMetaData\ và đặt file Phishing-Sysmon_1033.MTA vào (bỏ phần tiền tố lạ nếu tên file bị đổi khi tải lên/xuống).
  3. Win+R → eventvwr.msc → menu Action → Open Saved Log… → chọn file .evtx → đặt tên → OK. Log hiện trong Saved Logs.
File .MTA là gì? Nó giống cuốn từ điển đi kèm: chứa các chuỗi mô tả như "Process Create (rule: ProcessCreate)", "File created"… Nếu máy bạn không cài Sysmon mà thiếu file này, tab General sẽ báo "The description for Event ID … cannot be found" và cột Task Category trống. Dữ liệu vẫn còn nguyên trong tab Details, nhưng có cuốn từ điển thì đọc dễ hơn nhiều, và chức năng Find mới tìm được trong phần mô tả.

Đọc một event ở đâu? Chọn event → khung dưới:

  • General: mô tả dạng văn bản (UtcTime, ProcessId, Image…) — đọc nhanh.
  • Details → Friendly View: mở mục EventData, mỗi dòng là một field. Details → XML View: thấy đúng tên field (<Data Name="ProcessGuid">) để viết filter XPath.

B1Nhìn tổng quan

  • Bấm vào tiêu đề cột Event ID để sắp xếp, hoặc cột Task Category để gom theo loại.
  • Bấm cột Date and Time để sắp theo thời gian (cũ → mới) — đọc như xem lại băng camera.
Cột Date and Time hiển thị theo múi giờ máy bạn (Việt Nam UTC+7 → 21/05/2025 01:58). Field UtcTime trong event là giờ UTC (2025-05-20 18:58). Khi đối chiếu với đề bài hoặc log khác, nhớ quy đổi.

B2File download qua browser ID 11 ID 15

  1. Khung phải (Actions) → Filter Current Log… → ô <All Event IDs> gõ 11,15 → OK.
  2. Chọn lần lượt từng event, tab General, nhìn dòng Image: — tìm các dòng có msedge.exe.
  3. Đọc TargetFilename: → thấy …\Downloads\Unconfirmed 109024.crdownload rồi …\Downloads\top-cats.zip.
  4. Xác nhận URL: Actions → Find… → gõ HostUrl → Find Next. Event 15 (Record 4822) có Contents: … HostUrl=http://10.14.97.15/top-cats-2025/top-cats.zip.

Muốn xem Record ID: tab Details → Friendly View → mở mục System → EventRecordID.

B3Thư mục giải nén ID 11 ID 15

  1. Vẫn giữ filter 11,15. Tìm event có Image: C:\Windows\Explorer.EXE.
  2. Event 11 lúc 18:58:43: TargetFilename: C:\Users\Administrator\Pictures\best-cat.jpg.exe.
  3. Xác nhận nó đến từ zip: Find… → ReferrerUrl=C:\ → các event 15 có ReferrerUrl=C:\Users\Administrator\Downloads\top-cats.zip, đều nằm trong …\Pictures\.
  4. Mở tab Details của event Explorer, copy ProcessGuid = {c5d2b969-2e42-682b-4a02-000000001801}. Dùng ở B4.

B4PID của malware ID 1

Cách dễ: Filter Current Log → Event IDs: 1 → xem cột thời gian ngay sau lúc giải nén (18:58:43) và đọc dòng Image.

Cách chuẩn (lọc theo cha): chỉ lấy process có cha là explorer:

  1. Filter Current Log → Event IDs 1 → chuyển sang tab XML → tick Edit query manually (bấm Yes).
  2. Giữ nguyên các dòng Path="file://…" mà Event Viewer tự sinh, chỉ thay nội dung trong <Select>:
<QueryList>
  <Query Id="0" Path="file://C:\Labs\Phishing-Sysmon.evtx">
    <Select Path="file://C:\Labs\Phishing-Sysmon.evtx">
      *[System[(EventID=1)]]
      and
      *[EventData[Data[@Name='ParentProcessGuid']='{c5d2b969-2e42-682b-4a02-000000001801}']]
    </Select>
  </Query>
</QueryList>

Kết quả còn 3 event: 2 × mspaint.exe (mở ảnh mồi) và best-cat.jpg.exe → ProcessId: 5484. Copy ProcessGuid của nó: {c5d2b969-d0fa-682c-2b05-000000001801}.

B5Domain độc hại ID 22

  1. Filter Current Log → Event IDs 22 → có 4 event. Hai cái của SystemSettings.exe (onecs-live.azureedge.net, của Microsoft) là nhiễu.
  2. Hai cái còn lại có Image: C:\Users\Administrator\Pictures\best-cat.jpg.exe, ProcessId: 5484 → QueryName: rjj.store.

Lọc chính xác bằng XML (tab XML → Edit query manually):

*[System[(EventID=22)]]
and
*[EventData[Data[@Name='ProcessGuid']='{c5d2b969-d0fa-682c-2b05-000000001801}']]

Bỏ (EventID=22), chỉ để điều kiện ProcessGuid → thấy toàn bộ hoạt động của malware (ID 1, 22, 22, 5).

B6Đi ngược lên cha bằng Find

  1. Mở event ID 1 của best-cat.jpg.exe, đọc ParentProcessId: 2788, ParentImage: C:\Windows\explorer.exe, copy ParentProcessGuid.
  2. Clear Filter → Actions → Find… → dán GUID → Find Next. Mỗi lần Find Next là nhảy tới event kế tiếp có GUID đó (ID 11, 2, 15, 13 của explorer, và các ID 1 của con nó).
Explorer (PID 2788) đã chạy trước khi log được thu, nên không có event ID 1 của chính explorer. Ta xác nhận nó qua các event khác mang cùng ProcessGuid. Đây là chuyện rất hay gặp: log chỉ là "đoạn băng" ghi trong một khoảng thời gian.
Giới hạn của XPath trong Event Viewer: chỉ so khớp bằng chính xác (=), không có contains() hay wildcard. Muốn tìm theo một phần chuỗi (vd. "HostUrl", ".jpg.exe") thì dùng Find…, hoặc chuyển sang PowerShell với -match.

👪 Làm sao biết event này là "con" của event khác?

Nghĩ như sổ hộ khẩu: mỗi event ID 1 (Process Create) ghi tên đứa trẻ (Image), số CCCD của nó (ProcessGuid) và số CCCD của bố/mẹ (ParentProcessGuid). Muốn tìm bố → lấy ParentProcessGuid của con đi dò cột ProcessGuid ở các event khác.

Muốn biếtSo fieldvới field

Ở ID 10 tên field là SourceProcessGUID (chữ GUID viết hoa). PowerShell không phân biệt hoa/thường, nhưng XPath trong Event Viewer thì có phân biệt, phải gõ đúng.
