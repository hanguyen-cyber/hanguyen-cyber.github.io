Task 1 Vì sao RDP là cửa ngõ bị tấn công nhiều nhất

RDP (Remote Desktop Protocol), mặc định cổng TCP 3389, cho phép điều khiển máy Windows từ xa như đang ngồi trước màn hình. Khi máy chủ mở RDP thẳng ra Internet, bot trên toàn thế giới sẽ liên tục thử user/password — thường chỉ vài phút sau khi máy được bật.

🔑 Ví dụ dễ hiểu: RDP giống cửa chính của nhà xưởng. Kẻ trộm không phá cửa mà đứng thử từng chìa khóa trong chùm hàng nghìn chiếc (brute-force), hoặc thử một chìa "phổ biến" lên hàng trăm ổ khóa khác nhau (password spraying). Camera an ninh của bạn chính là Security.evtx — nó ghi lại mỗi lần thử chìa, đúng hay sai.

Hai kiểu tấn công phổ biến

Brute-force1 user (vd: Administrator) × rất nhiều mật khẩuHàng trăm 4625 cùng TargetUserName, cùng IP, trong vài phút

⚠ Bẫy thường gặp: Nhiều người chỉ lọc 4625 với Logon Type 10 và kết luận "không có brute-force". Với NLA (mặc định từ Windows Server 2012), lỗi RDP xuất hiện dưới dạng Type 3. Hãy luôn lọc cả Type 3 và 10, rồi xem thêm trường IpAddress và WorkstationName.

Task 4 Chuỗi sự kiện của một vụ RDP Breach

Một sự kiện đơn lẻ không nói lên nhiều. Cái cần tìm là câu chuyện: nhiều lần thất bại → một lần thành công từ cùng IP → hành vi bất thường ngay sau đó.

02:14:03 → 02:31:47
4625 × 1,284 — Logon Type 3, user administrator, admin, user… từ 203.0.113.45
02:31:52
1149 (RemoteConnectionManager) — User: svc_backup, Source: 203.0.113.45
02:31:53
4624 — Logon Type 10, svc_backup, IP 203.0.113.45 → ghi lại Logon ID 0x3E7A1F
02:31:55
21 / 22 (LocalSessionManager) — Session logon + Shell start
02:33:10
4688 — cmd.exe → whoami /all, net user, net localgroup administrators
02:36:41
4720 + 4732 — Tạo user support$ và thêm vào nhóm Administrators (persistence)
02:48:02
1102 — Audit log bị xóa (xóa dấu vết)
🎬 Ví dụ dễ hiểu: Giống xem lại camera: 17 phút một người thử chìa liên tục (4625) → cánh cửa mở (4624 Type 10) → người đó đi thẳng vào phòng giám đốc lục hồ sơ (4688 whoami/net user) → làm thêm một chìa khóa dự phòng (4720/4732) → cuối cùng rút thẻ nhớ camera (1102).
🔗 Logon ID là "sợi chỉ đỏ": lấy TargetLogonId của 4624 rồi tìm nó trong trường SubjectLogonId của các event 4688/4720/4732 để biết hacker đã làm gì trong phiên đó.

Task 5 Lọc log bằng Event Viewer & PowerShell

Cách 1 — Event Viewer (GUI)

  1. Mở eventvwr.msc → Windows Logs → Security (hoặc Action → Open Saved Log… để mở file .evtx thu thập được).
  2. Filter Current Log… → nhập 4624,4625 vào ô Event IDs.
  3. Để lọc chính xác Logon Type, chuyển sang tab XML → Edit query manually:
 XML Filter — đăng nhập RDP thành công
<QueryList>
  <Query Id="0" Path="Security">
    <Select Path="Security">
      *[System[(EventID=4624)]]
      and *[EventData[Data[@Name='LogonType']='10']]
    </Select>
  </Query>
</QueryList>

Cách 2 — PowerShell (nhanh khi log lớn)

 PowerShell — Top IP brute-force
# Đếm số lần đăng nhập thất bại theo IP nguồn
Get-WinEvent -Path .\Security.evtx -FilterXPath "*[System[EventID=4625]]" |
  ForEach-Object {
    $x = [xml]$_.ToXml()
    $d = @{}; $x.Event.EventData.Data | % { $d[$_.Name] = $_.'#text' }
    [pscustomobject]@{ IP=$d.IpAddress; User=$d.TargetUserName; Type=$d.LogonType }
  } |
  Group-Object IP | Sort-Object Count -Descending |
  Select-Object Count, Name -First 10
 PowerShell — IP nào vừa thất bại vừa thành công?
$fail = Get-WinEvent -Path .\Security.evtx -FilterXPath "*[System[EventID=4625]]" |
  % { ([xml]$_.ToXml()).Event.EventData.Data | ? Name -eq 'IpAddress' | % '#text' } |
  Sort-Object -Unique

Get-WinEvent -Path .\Security.evtx -FilterXPath `
  "*[System[EventID=4624]] and *[EventData[Data[@Name='LogonType']='10' or Data[@Name='LogonType']='3']]" |
  % {
    $d=@{}; ([xml]$_.ToXml()).Event.EventData.Data | % { $d[$_.Name]=$_.'#text' }
    if ($fail -contains $d.IpAddress) {
      [pscustomobject]@{ Time=$_.TimeCreated; User=$d.TargetUserName; IP=$d.IpAddress;
                         Type=$d.LogonType; LogonId=$d.TargetLogonId }
    }
  } | Format-Table -AutoSize   # ← mỗi dòng ở đây là một BREACH tiềm năng
🛠 Công cụ tự động hóa khi có nhiều file: Hayabusa và Chainsaw (dùng rule Sigma) quét hàng loạt .evtx và gắn cờ brute-force/RDP logon đáng ngờ chỉ trong vài giây.

Task 6 Sau khi vào được: hacker làm gì tiếp?

Một lần 4624 Type 10 từ IP lạ chưa chắc là tấn công (có thể là IT đang làm việc từ xa). Bằng chứng mạnh nhất là hành vi ngay sau khi đăng nhập:

Giai đoạnEvent IDVí dụ
Discovery (trinh sát)4688 / Sysmon 1whoami, net user, ipconfig /all, nltest /dclist
Persistence4720, 4732, 7045, 4698Tạo user mới, thêm vào Administrators, cài service, tạo Scheduled Task
Defense Evasion1102, 104 (System), Defender 5001Xóa log Security/System, tắt Real-time Protection
Execution / Impact4688, PowerShell 4104Tải malware, chạy ransomware, vssadmin delete shadows
🚨 Dấu hiệu "chắc chắn có chuyện": 4625 hàng loạt → 4624 Type 10 cùng IP → trong vòng vài phút có 4720/4732 hoặc 1102. Đây là lúc cần isolate máy ngay.
Lưu ý: Event 4688 chỉ có nếu bật Audit Process Creation; muốn thấy cả command line phải bật thêm "Include command line in process creation events". Nếu không có, hãy tìm trong Sysmon hoặc PowerShell Operational log.

Task 7 Checklist điều tra & câu hỏi luyện tập

Checklist khi nhận file .evtx nghi bị RDP breach

  • Đếm 4625 theo IP và theo user — có IP nào vượt hàng chục/hàng trăm lần?
  • Xem SubStatus: 0xC0000064 (dò tên) hay 0xC000006A (đoán mật khẩu user có thật)?
  • Tìm 4624 Type 10 (và Type 3) từ chính các IP đó — ghi lại thời gian, user, Logon ID.
  • Đối chiếu 1149 và 21/22/24/25 trong TerminalServices log để xác nhận phiên RDP.
  • Lần theo Logon ID → 4688, 4720, 4732, 7045, 4698 trong phiên đó.
  • Kiểm tra 1102 / 104 — log có bị xóa không? Khoảng thời gian nào bị "trống"?
  • Kiểm tra WorkstationName lạ (kali, WIN-XXXX, rỗng) và IP ngoài phạm vi công ty.
  • Khuyến nghị: tắt RDP ra Internet, dùng VPN/MFA, bật NLA, khóa tài khoản sau N lần sai.
