Detecting Collection: phát hiện kẻ tấn công đang “gom đồ”

Tham chiếu: TryHackMe – Windows Threat Detection 2, Task 5 “Detecting Collection” · Góc nhìn Blue Team / SOC

Hình dung: Ở bước Discovery, kẻ trộm đi một vòng xem trong nhà có gì. Đến bước Collection, hắn bắt đầu mở ngăn kéo, nhặt đồ bỏ vào túi rồi buộc túi lại trước khi ra cửa. Người bảo vệ không cần đoán hắn lấy món gì. Chỉ cần thấy ba hành động là đủ báo động: tay chạm vào két, túi đang được đóng gói, và có người xách túi ra cửa.

① Tìm và mởLục tìm file theo đuôi hoặc từ khoá, mở file nhạy cảm
② Gom về một chỗCopy vào thư mục tạm (staging)
③ Đóng góiNén thành .zip / .7z
④ Mang ra ngoàiKết nối mạng ra ngoài ngay sau khi nén (Exfiltration)

Mỗi bước để lại dấu vết ở một loại log khác nhau. Một bước riêng lẻ có thể là việc bình thường, còn cả chuỗi diễn ra liên tiếp từ cùng một tiến trình mới là tín hiệu mạnh.

Hai kiểu Collection, hai cách để lại dấu vết

👤 Người thật ngồi gõ lệnh (hands-on-keyboard)

  • Hay gặp khi tấn công mạng doanh nghiệp lớn: kẻ tấn công biết mình cần gì và có nhiều thời gian để tìm.
  • Dùng công cụ có sẵn như Notepad, WordPad, CMD, PowerShell, 7-Zip.
  • Dễ thấy: mọi lệnh đều sinh tiến trình mới, ghi lại đầy đủ dòng lệnh trong Sysmon Event 1.
  • Ví dụ thực tế trong room (theo The DFIR Report): mở file DOCX/TXT bằng Notepad, WordPad rồi nén tất cả bằng 7-Zip.

🤖 Data stealer (malware tự động)

  • Hay gặp ở máy cá nhân, không cần người điều khiển. Cả quá trình thường xong trong chưa tới một phút.
  • Thường tự đọc file bằng code của chính nó, ít khi gọi CMD/PowerShell.
  • Khó hơn: không có dòng lệnh nào cho biết đã lấy file nào. Phải dựa vào file được tạo ra (Event 11), truy cập file (4663) và kết nối mạng (Event 3/22).
  • Ví dụ trong room: Gremlin stealer (theo Unit 42).

Quy trình điều tra trong lab Task 5

Áp dụng sau khi chạy mẫu stealer.exe trong thư mục Practice\Task 5. Các bước dưới đây chỉ chỉ chỗ cần nhìn, không ghi sẵn đáp án.

  1. Mở Applications and Services Logs → Microsoft → Windows → Sysmon → Operational, bấm Filter Current Log với Event IDs 1,11,22,3.
  2. Dùng Find… tìm stealer.exe và ghi lại ProcessGuid (hoặc ProcessId) của nó. Mọi thứ phía sau đều xoay quanh mã này.
  3. Thư mục malware tạo ra: xem các Event 11 có Image là stealer.exe, đọc TargetFilename. Phần thư mục chung của các file là chỗ staging.
  4. Loại file malware tìm kiếm: xem Event 1 có ParentImage là stealer.exe. Trong CommandLine của lệnh tìm kiếm sẽ có các tham số như -Include / -Filter kèm đuôi file.
  5. Cmdlet đọc clipboard: vẫn trong các Event 1 đó, tìm dòng lệnh PowerShell có chữ Clipboard.
  6. Domain nhận dữ liệu: lọc Event 22, xem QueryName của các truy vấn có thời gian ngay sau khi file nén được tạo. Bỏ qua domain hệ thống của Microsoft/AWS.

Truy vấn PowerShell hỗ trợ

# Mọi sự kiện Sysmon 1/11/22/3 liên quan đến một tiến trình (đổi tên ở dòng đầu)
$name = 'stealer.exe'
Get-WinEvent -LogName 'Microsoft-Windows-Sysmon/Operational' |
  Where-Object { $_.Id -in 1,11,22,3 } |
  ForEach-Object {
    $d = @{}; ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    if ($d.Image -like "*$name" -or $d.ParentImage -like "*$name") {
      [pscustomobject]@{
        Time   = $_.TimeCreated
        Event  = $_.Id
        Image  = Split-Path $d.Image -Leaf
        Detail = $d.CommandLine + $d.TargetFilename + $d.QueryName + $d.DestinationHostname
      }
    }
  } | Sort-Object Time | Format-Table -AutoSize -Wrap
# File nén mới được tạo (Sysmon 11): dấu hiệu "buộc túi"
Get-WinEvent -LogName 'Microsoft-Windows-Sysmon/Operational' -FilterXPath "*[System[EventID=11]]" |
  Where-Object { $_.Message -match '\.(zip|7z|rar)\b' } |
  Select-Object TimeCreated, @{n='Detail';e={($_.Message -split "`n" | Select-String 'Image|TargetFilename') -join ' | '}}

Ý tưởng quy tắc phát hiện cho SIEM

Quy tắc 1: chuỗi “gom → nén → gửi” trong thời gian ngắn

Cùng một ProcessGuid (hoặc cây tiến trình): có Event 11 tạo file .zip/.7z, rồi trong vòng 5 phút có Event 3/22 ra domain chưa từng gặp. Độ tin cậy cao, hiếm khi báo nhầm.

Quy tắc 2: tiến trình lạ đọc dữ liệu của ứng dụng khác

Bật SACL trên thư mục profile của trình duyệt, ứng dụng chat, ví điện tử, thư mục .ssh. Cảnh báo khi Event 4663 cho thấy tiến trình không phải chính ứng dụng đó đọc file. Ví dụ: một exe trong Downloads đọc dữ liệu của Chrome.

Quy tắc 3: tìm từ khoá nhạy cảm trong dòng lệnh

Event 1/4688 có findstr hoặc Select-String đi kèm từ khoá như password, pass, secret, key, và có ghi kết quả ra file.

Quy tắc 4: đọc clipboard từ tiến trình nền

Event 4104 hoặc Event 1 có Get-Clipboard, với tiến trình cha không phải phiên PowerShell mà người dùng tự mở.

Quy tắc 5: thư mục staging bất thường

Event 11: một tiến trình tạo hàng loạt file trong C:\Temp, %TEMP%, C:\ProgramData hoặc C:\PerfLogs trong vòng vài giây.

Checklist cấu hình log để không bị “mù”

  • ☐ Đã cài Sysmon với cấu hình bật Event 1, 3, 11, 22 (ví dụ cấu hình SwiftOnSecurity hoặc olafhartong/sysmon-modular).
  • ☐ Đã bật Audit Process Creation và Include command line in process creation events (4688).
  • ☐ Đã bật PowerShell Script Block Logging (4104).
  • ☐ Đã bật Audit File System và đặt SACL lên các thư mục dữ liệu nhạy cảm (4663).
  • ☐ Log được đẩy về SIEM. Malware có thể xoá log trên máy, còn bản trên SIEM thì vẫn giữ lại.
