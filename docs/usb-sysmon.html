🧠 Tư duy điều tra: USB worm đi đường nào?

Bài này khác bài Phishing: file độc không đến từ Internet mà nằm sẵn trên USB. Hãy hình dung nó như một người lạ cầm thẻ nhân viên giả: file tên "Open Sandisk 4GB USB.exe" giả làm nút "mở ổ USB", user tưởng bấm vào để xem dữ liệu, thực ra là mời nó vào nhà. Vào rồi, nó làm 3 việc quen thuộc của USB worm:

Chìa khoá của bài này: ký tự ổ đĩa. Trên Windows, ổ hệ thống gần như luôn là C:. Một file thực thi chạy từ E:\ hay F:\ thường là USB, ổ mạng hoặc ổ gắn ngoài. Chỉ cần lọc "đường dẫn không bắt đầu bằng C:\" là các thứ đến từ USB lộ ra ngay.
Xâu chuỗi vẫn bằng ProcessGuid (như số CCCD của process). Bài này còn có ví dụ thật về chuyện PID bị dùng lại, xem mục Bẫy thường gặp.

🛠️ Step by step

Chạy trên Windows PowerShell 5.1 hoặc PowerShell 7 trên Windows. Sửa $Path thành đường dẫn thật của file .evtx.

B0Nạp log và tách field thành cột

Giống bài Phishing: biến mỗi <Data Name="..."> trong XML thành một cột để lọc cho dễ.

$Path = "C:\Labs\USB-Sysmon.evtx"   # <-- sửa đường dẫn
$Raw  = Get-WinEvent -Path $Path -Oldest

function ConvertTo-SysmonObject {
    process {
        $xml = [xml]$_.ToXml()
        $o = [ordered]@{
            RecordId = $_.RecordId
            EventId  = $_.Id
            Time     = $_.TimeCreated
        }
        foreach ($d in $xml.Event.EventData.Data) { $o[$d.Name] = $d.'#text' }
        [pscustomobject]$o
    }
}

$Ev = $Raw | ConvertTo-SysmonObject
$Ev.Count     # 39

B1Tổng quan

$Ev | Group-Object EventId | Sort-Object Count -Descending | Select-Object Count, Name

Kết quả: ID 1 (16), 22 (8), 10 (7), 13 (5), 11 (3). Có ID 1 → biết được ai chạy cái gì; có ID 11 → biết được file nào được tạo ở đâu; có ID 13 → có thay đổi registry.

B2File USB nào được user chạy? ID 1

a) Tìm process chạy từ ổ khác C:

$Ev | Where-Object { $_.EventId -eq 1 -and $_.Image -notmatch '^C:\\' } |
      Select-Object RecordId, Time, ProcessId, ProcessGuid, Image, CurrentDirectory, ParentImage

Trong regex, ^C:\\ nghĩa là "bắt đầu bằng C:\" (dấu \ phải viết đôi). -notmatch lấy những dòng không khớp.

Kết quả mong đợi 
RecordId         : 4928
ProcessId        : 1108
ProcessGuid      : {c5d2b969-d92e-682c-9205-000000001801}
Image            : E:\Open Sandisk 4GB USB.exe
CurrentDirectory : E:\
ParentImage      : C:\Windows\explorer.exe
→ User double-click (cha là explorer.exe) file E:\Open Sandisk 4GB USB.exe, PID 1108.

b) Mở rộng: có ổ USB nào khác xuất hiện trong CommandLine không?

$Ev | Where-Object { $_.EventId -eq 1 -and $_.CommandLine -match '\b[D-Z]:\\' } |
      Select-Object RecordId, Time, Image, CommandLine | Format-List

Bạn sẽ thấy thêm Record 4916: chrome.exe mở F:\tryhackme-report-2025.pdf lúc 19:31:56. Nghĩa là ổ F: đã được cắm vào máy từ trước. Thông tin này sẽ có ích ở B4. Đây là mở file PDF để xem chứ không phải "chạy" chương trình, nên không phải đáp án câu 1.

B3Malware thả file gì xuống ổ đĩa? ID 11 ID 13

Lấy GUID của malware ở B2, rồi tìm mọi file nó tạo ra:

$Mal = $Ev | Where-Object { $_.EventId -eq 1 -and $_.Image -eq 'E:\Open Sandisk 4GB USB.exe' }

$Ev | Where-Object { $_.EventId -eq 11 -and $_.ProcessGuid -eq $Mal.ProcessGuid } |
      Select-Object RecordId, Time, TargetFilename
Kết quả mong đợi 
RecordId Time                 TargetFilename
-------- ----                 --------------
    4929 ... 19:34:06         C:\Users\Public\Documents\winupdate.exe
    4931 ... 19:34:06         F:\Open Data Traveler 32 GB USB.exe
→ File thả xuống ổ đĩa hệ thống: C:\Users\Public\Documents\winupdate.exe. Tên "winupdate" giả làm Windows Update, đặt trong thư mục Public mà mọi user đều ghi được.

Kiểm tra persistence: file thả xuống có được cài để tự chạy không?

$Ev | Where-Object { $_.EventId -eq 13 -and $_.ProcessGuid -eq $Mal.ProcessGuid } |
      Select-Object RecordId, TargetObject, Details | Format-List

→ HKU\…\Software\Microsoft\Windows\CurrentVersion\Run\WinUpdate = C:\Users\Public\Documents\winupdate.exe. Mỗi lần Administrator đăng nhập, winupdate.exe sẽ tự chạy.

B4Malware lây sang USB nào? ID 11

Trong các file malware tạo ra, file nào nằm ở ổ không phải C: và không phải ổ nguồn E:?

$Ev | Where-Object { $_.EventId -eq 11 -and $_.TargetFilename -notmatch '^C:\\' } |
      Select-Object RecordId, Time, Image, TargetFilename
Kết quả mong đợi Record 4931: E:\Open Sandisk 4GB USB.exe tạo F:\Open Data Traveler 32 GB USB.exe.
→ Malware lây sang USB ở ổ F:, đặt tên giả "Open Data Traveler 32 GB USB.exe". Data Traveler là dòng USB của Kingston, cùng một chiêu đội lốt như file gốc trên ổ E: (SanDisk). Kết hợp với B2b (PDF trên F:) → khẳng định F: là một USB khác.

B5Toàn bộ hành vi của malware + cây process

# Mọi event mang GUID của malware
$Ev | Where-Object { $_.ProcessGuid -eq $Mal.ProcessGuid } |
      Select-Object RecordId, Time, EventId, TargetFilename, TargetObject

# Cây process (giống bài Phishing)
function Show-Tree($Guid, $Indent = 0) {
    $kids = $Ev | Where-Object { $_.EventId -eq 1 -and $_.ParentProcessGuid -eq $Guid }
    foreach ($k in $kids) {
        '{0}|-- [{1}] {2}' -f (' ' * $Indent), $k.ProcessId, $k.CommandLine
        Show-Tree $k.ProcessGuid ($Indent + 4)
    }
}
Show-Tree '{c5d2b969-2e42-682b-4a02-000000001801}'   # explorer.exe (PID 2788)

Kết quả: explorer có 2 con là chrome.exe (6588) và Open Sandisk 4GB USB.exe (1108). Malware không sinh process con nào.

⚡Lọc nhanh bằng FilterXPath (cho log lớn)

# Mọi file do malware tạo (so khớp chính xác GUID)
Get-WinEvent -Path $Path -FilterXPath "*[System[EventID=11] and EventData[Data[@Name='ProcessGuid']='{c5d2b969-d92e-682c-9205-000000001801}']]" |
    Format-List TimeCreated, Message

B0Mở file .evtx (kèm .MTA)

  1. Đặt USB-Sysmon.evtx vào C:\Labs\, và USB-Sysmon_1033.MTA vào C:\Labs\LocaleMetaData\ (đổi lại đúng tên nếu bị thêm tiền tố khi tải).
  2. eventvwr.msc → Action → Open Saved Log… → chọn file → OK.
  3. Đọc event ở tab General (dạng chữ) hoặc Details → Friendly View / XML View (từng field).
File .MTA là "cuốn từ điển" chứa tên các loại event Sysmon ("Process Create", "File created", "Registry value set"…). Thiếu nó trên máy không cài Sysmon thì tab General báo "description cannot be found" và Find không tìm được trong phần mô tả.

B1Tổng quan

  • Bấm cột Date and Time để sắp theo thời gian, cột Event ID / Task Category để gom theo loại.
  • Cột thời gian theo giờ máy bạn (UTC+7 → 21/05/2025 02:34), còn field UtcTime là giờ UTC (2025-05-20 19:34).

B2File USB nào được user chạy? ID 1

  1. Filter Current Log… → Event IDs: 1 → OK (còn 16 event).
  2. XPath không lọc được "không bắt đầu bằng C:\", nên dùng Find… (khung Actions) → gõ Image: E:\ → Find Next. Nếu chưa biết ổ nào, thử lần lượt Image: D:\, E:\, F:\…
  3. Cách khác: đọc lướt cột thời gian, chọn từng event và nhìn dòng Image:. Hầu hết là C:\Program Files (x86)\Google\…, chỉ một event có Image: E:\Open Sandisk 4GB USB.exe (19:34:06).
  4. Trong event đó đọc: ProcessId: 1108, CurrentDirectory: E:\, ParentImage: C:\Windows\explorer.exe. Copy ProcessGuid = {c5d2b969-d92e-682c-9205-000000001801}.

Gợi ý thêm: Find F:\ sẽ ra Record 4916, chrome mở F:\tryhackme-report-2025.pdf. Ổ F: đã có mặt trên máy từ trước khi malware chạy.

B3File malware thả xuống đĩa ID 11

  1. Filter Current Log → Event IDs 11 → tab XML → tick Edit query manually.
  2. Giữ nguyên các dòng Path="file://…" Event Viewer đã sinh, chỉ thay phần trong <Select>:
<QueryList>
  <Query Id="0" Path="file://C:\Labs\USB-Sysmon.evtx">
    <Select Path="file://C:\Labs\USB-Sysmon.evtx">
      *[System[(EventID=11)]]
      and
      *[EventData[Data[@Name='ProcessGuid']='{c5d2b969-d92e-682c-9205-000000001801}']]
    </Select>
  </Query>
</QueryList>

Còn 2 event. Event lúc 19:34:06.755: TargetFilename: C:\Users\Public\Documents\winupdate.exe → đáp án câu 2.

Persistence: đổi EventID=11 thành EventID=13 → thấy TargetObject: …\CurrentVersion\Run\WinUpdate, Details: C:\Users\Public\Documents\winupdate.exe.

B4Malware lây sang USB nào? ID 11

Vẫn dùng filter ở B3 (EventID 11 + GUID malware). Event còn lại (19:34:06.763) có TargetFilename: F:\Open Data Traveler 32 GB USB.exe → malware chép chính nó sang ổ F:.

Nếu chỉ filter 11 mà không có GUID, bạn sẽ thấy thêm event thứ 3: explorer.exe tạo Downloads\meeting-recordings.zip. Đó là của Explorer, không phải của malware, và diễn ra trước khi malware chạy → loại.

B5Xem toàn bộ hành vi malware

Xoá điều kiện EventID, chỉ để lại điều kiện GUID:

*[EventData[Data[@Name='ProcessGuid']='{c5d2b969-d92e-682c-9205-000000001801}']]

Kết quả 4 event, xảy ra trong vòng 0,25 giây: ID 1 (chạy) → ID 11 (winupdate.exe) → ID 13 (Run key) → ID 11 (chép sang F:). Tốc độ này cho thấy đây là hành vi tự động của chương trình, không phải người thao tác.

Đi ngược lên cha: copy ParentProcessGuid của event ID 1 → Clear Filter → Find… dán GUID → Find Next để thấy các event khác của explorer.exe (PID 2788).

Nhắc lại giới hạn XPath: chỉ so khớp chính xác, không có wildcard/contains. Tìm theo một phần chuỗi (như "E:\", "Run\") thì dùng Find…, hoặc chuyển sang PowerShell.
